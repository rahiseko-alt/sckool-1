# 公開の初心者ナビ（先生向け・専門用語なし）

生徒が自分の端末からアクセスできるように、インターネット上に置く手順です。
3つの無料サービスを使います。**すべて無料の範囲で収まります**（Oracle だけ本人確認の
カードが要りますが、課金はされません）。

**根拠と技術的な手順は `docs/deploy.md`、置き場所を選んだ理由は `docs/decisions.md`「42.」**に
あります。このファイルは、その内容を非エンジニアが1つずつ実行できる形に直したものです
（2026-09 に各社の公式ページで最新の手順・無料枠を確認しました）。

画面の前で、上から1つずつ実行してください。**「控える値」は必ずメモ帳などに書き写して
ください。** あとの手順で入力します。

用語は最小限にしています。

- **住所（URL）**: `https://...` で始まる、インターネット上の場所
- **控える値**: あとで別の画面に入力するために、いま書き写しておく文字列

---

## 全体の地図（何をどこに置くか）

| 置くもの                               | 置き場所             | お金                                             |
| -------------------------------------- | -------------------- | ------------------------------------------------ |
| 生徒のデータ（企業・お金・取引の記録） | **Aiven**            | 無料・期限なし・カード不要                       |
| サーバー本体（プログラムの動く機械）   | **Oracle Cloud**     | 無料・期限なし・**カードで本人確認**（課金なし） |
| 生徒が見る画面                         | **Cloudflare Pages** | 無料                                             |

**順番が大事です。** ①Aiven（データの箱）→②Oracle（機械）→③Cloudflare（画面）の順に作ります。
前の手順で「控える値」を、次の手順で使うからです。

---

## ① Aiven（生徒のデータの箱）を作る

1. https://aiven.io を開き、アカウントを登録する。**クレジットカードは要りません。**
2. 新しいサービスを作る画面で、**「PostgreSQL」**という種類を選ぶ。
3. プランは**「Free」**を選ぶ（1 CPU / メモリ 1 GB / 保存領域 1 GB。いまの規模なら足ります）。
4. 置く地域（region）は、日本から近い所を選ぶ。
5. サービスができたら、接続用の文字列（`postgres://` で始まる長い1行）を探してコピーする。
   - **この文字列を控える。** 名前は「DATABASE_URL（データベースの住所）」。②で使います。

**注意・落とし穴**

- **一度も使わずに数時間置くと、自動で停止されます**（公式仕様）。長く使わないときも
  停止されますが、**停止の前にメールで知らせが来ます**。停止されても、Aiven の画面から
  いつでも起動し直せます。授業の前には起動しているか確認してください。
- **無料プランに「自動バックアップ」は付いていません**（2026-09 時点、公式に記載なし）。
  大事なデータを守りたい月末などは、別途データの控え（エクスポート）を取ってください。
  やり方の例（エンジニア向け）: `pg_dump "<DATABASE_URL>" > backup.sql`

---

## ② Oracle Cloud（サーバー本体）を作る

**ここだけカードが要ります。本人確認のためで、課金はされません**（申込時に1ドルの
仮押さえをして即座に取り消す、と公式に書かれています）。使えるのは、PIN の要らない
クレジットカードか、クレジットカード扱いのデビットカードです（プリペイド・使い捨ては不可）。

1. https://www.oracle.com/cloud/free/ を開き、無料アカウントを申し込む。
2. **「本拠地リージョン（home region）」を慎重に選ぶ。**
   - **申し込みのあと、この地域は二度と変えられません**（公式明記）。日本で使うなら
     日本の地域を選んでください。
3. 支払い方法の確認でカードを登録する（課金はされません）。
4. アカウントができたら、**「Ampere A1（Arm）」**という種類の機械（Compute インスタンス）を
   1台作る。無料の範囲は **2コア・メモリ 12 GB・ディスク 200 GB** までです。
   - **もし `out of host capacity`（枠が空いていません）と出たら**: 別の
     「可用性ドメイン（Availability Domain）」を選んで作り直すか、時間をおいて
     もう一度試してください（この待避策は公式手順ではなく、経験則です）。
5. できた機械に、プログラムを動かす準備をする（この作業はエンジニア向けです）:
   - Node 22 と pnpm を入れる
   - Redis を入れて動かす（この機械の上でよい。消えても困りません）
   - このプロジェクトのプログラムを取ってきて、下の「渡す値」を設定して起動する

**この機械に渡す値（環境変数）**

| 名前            | 中身                                                           |
| --------------- | -------------------------------------------------------------- |
| `DATABASE_URL`  | ①で控えた Aiven の接続文字列                                   |
| `REDIS_URL`     | `redis://localhost:6379`                                       |
| `STORE_CORS`    | ③で決まる「生徒の画面の住所」                                  |
| `AUTH_CORS`     | ③で決まる「生徒の画面の住所」（**STORE_CORS と両方に入れる**） |
| `JWT_SECRET`    | 長いランダムな文字列（**最重要。下の警告を必ず読む**）         |
| `COOKIE_SECRET` | 長いランダムな文字列（**同上**）                               |

6. 表を作る（`pnpm run api:migrate`）→ 公開鍵を作る（`pnpm run seed`）。
7. **出てきた「公開鍵」（`pk_` で始まる67文字）を控える。** ③で使います。
8. **このサーバーの住所を控える。** ③で使います。

**注意・落とし穴**

- **`STORE_CORS` と `AUTH_CORS` は必ず両方に入れる。** 片方だけだと
  「市場は開けるのにログインだけできない」という分かりにくい不具合になります（実際に起きました）。
- ③の画面を先に作ってから住所が決まるので、`STORE_CORS`／`AUTH_CORS` は③のあとに
  設定し直しても構いません。

---

## ③ Cloudflare Pages（生徒が見る画面）を作る

1. Cloudflare にログインし、左メニューの **「Workers & Pages」**を開く。
2. **「Create application」→「Pages」→「Connect to Git」**を選ぶ。
3. GitHub と接続し、このプロジェクトのリポジトリを選ぶ。
4. 組み立て（ビルド）の設定を、次のとおり入力する。

   | 設定項目                                     | 入れる値                                 |
   | -------------------------------------------- | ---------------------------------------- |
   | Framework preset（ひな型）                   | None（なし）                             |
   | Build command（組み立て命令）                | `pnpm --filter @sckool/storefront build` |
   | Build output directory（出来上がりの置き場） | `apps/storefront/dist`                   |
   | Root directory（大もとの場所）               | 変更しない（リポジトリの一番上のまま）   |

5. **環境変数を2つ**入力する（この画面の「Environment variables」欄）。**片方でも欠けると、
   市場に商品が1つも出ません。**

   | 名前                   | 中身                        |
   | ---------------------- | --------------------------- |
   | `VITE_BACKEND_URL`     | ②で控えたサーバーの住所     |
   | `VITE_PUBLISHABLE_KEY` | ②で控えた公開鍵（`pk_...`） |

6. 保存して組み立てる。できあがった画面の住所が「生徒の画面の住所」です。
7. **②に戻り、`STORE_CORS` と `AUTH_CORS` にこの住所を入れて、サーバーを起動し直す。**

**注意・落とし穴**

- **環境変数（VITE\_...）は組み立てるときに画面へ埋め込まれます。** あとで値を変えたら、
  **必ず組み立て直して**ください（値を書き換えるだけでは画面に反映されません）。
- 無料枠は組み立て500回/月まで。授業のたびに作り直しても十分です。

## 最重要の警告 — 本番用の秘密鍵を必ず設定する

**`JWT_SECRET` と `COOKIE_SECRET` に、開発用の初期値をそのまま使ってはいけません。**
必ず、長いランダムな文字列を自分で作って設定してください。

- **設定しないと、誰でも他の企業になりすませてしまいます**（ログインの偽造ができてしまう）。
  生徒が他社のお金を勝手に使える状態になります。
- 作り方の例（機械で1行、ランダムな文字列を作る）:
  `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`
  これを2回実行して、それぞれ `JWT_SECRET`・`COOKIE_SECRET` に使ってください。
- **この2つの値は、Aiven の接続文字列と同じくらい大事な秘密です。** 人に見せない・
  GitHub に書かない・チャットに貼らないでください。

（背景: この項目は監査報告 `docs/audit-report.md` の C-1 に対応します。）

## 授業の前に毎回たしかめる3つ

無料のサービスは「必ず動き続ける」保証がありません。授業の直前に開いて確認してください。

1. 生徒の画面が開き、商品が並ぶ
2. 自分のアカウントでログインできる
3. 管理画面が開く

Aiven が停止していたら、Aiven の画面から起動し直してください（数分かかることがあります）。
