## 満たさなかったものの詳細

### A3 個人情報を入れられるAPIが開いたままになっている

検査コマンドは何度実行しても違反0件でした。問題は「いま入っていないか」ではなく
「入れられるか」のほうです。基準 A3 は「生徒がそれらの項目を入力できる画面・API を
**一切持たない**」と書いています。

土台（Mercur / Medusa）が最初から持っている API を、生徒として実際に呼びました。

1. `POST /auth/customer/emailpass/register` に `tanaka@example.com` を渡す → **200**（合鍵が出た）
2. その合鍵で `POST /store/customers` に 氏名・メールアドレス・電話番号を渡す → **200**
3. データベースに `tanaka@example.com` / 太郎 / 田中 / 090-1234-5678 が保存された
4. `pnpm run check:no-personal-data` を実行 → **違反4件で失敗**（検査そのものは正しく働く）

つまり **検査は正しいが、入れる穴が塞がれていない**状態です。生徒の画面にその入口は
ありませんが、基準は「画面・API を一切持たない」と書いています。

（確認のあと、入れたデータは削除し、検査が再び違反0件になることを確かめました。）

### A5 管理画面にパスワード初期化のページが無い

基準は「**管理者画面で** Market ID を指定すると一時パスワードが発行され、画面に表示される」です。

- API は動きます。`POST /admin/accounts/reset-password` に `MKT-RQV2-SEV3` を渡すと
  200 で一時パスワード `57WR8H3F72Y7` と新しい再発行コードが返りました
- しかし管理画面（`http://localhost:7200/dashboard`）にログインして左メニューを見ると、
  この仕組みが足したページは **企業一覧・先生の購入ログ・取引の偏り の3つだけ**です
- 企業一覧のページにも初期化のボタンはありません

先生がパスワードを初期化するには、画面ではなく開発者向けの操作が必要です。

### B1 企業名を後から変えられない

「1〜40文字」「他社と重複できない」は正しく働きます。変更だけができません。

- 名前を変える処理（`rename`）はプログラムの中に用意されています
- しかし**その処理を呼び出しているところがリポジトリ全体で1か所もありません**
- 名前を変える HTTP の入口も、画面のボタンもありません

生徒が企業名を打ち間違えたまま作ってしまうと、直せません。

### B3 ボーナスの期限が切れると「残高」と「履歴の合計」が食い違う

ふだんは一致します。60社375件の同時購入テストでも食い違いは0社でした。
崩れるのは**ボーナスの有効期限（7日）が過ぎたとき**です。

実際に確かめた手順:

1. テストに満点で答えてボーナス1,500MPを受け取る（残高 通常100,000／ボーナス1,500）
2. データベースでそのボーナスの期限を1日前に書き換える（＝7日待つのと同じ状態）
3. 画面が使う残高 → 100,000（期限切れは数えないので正しい）
4. 履歴の合計 → **101,500**（+100,000 と +1,500 が残ったまま）

差が出るのは、下の E2 に書く「失効の行」が作られないためです。
本来はここに `−1,500` の行が入って、両方が100,000でそろうはずでした。

### E2 「失効」の行を作る処理が、どこからも呼ばれていない

期限切れのボーナスが残高に数えられないこと、支払いに使われないことは確認できました。
足りないのは「取引履歴に『失効』の行が残る」の部分です。

- 失効の行を作る処理（`expireBonuses`）は用意されています
- しかしそれを呼んでいるのは**検査用のスクリプト1本だけ**です。定期実行の仕組み（`apps/api/src/jobs`）は
  空で、HTTPの入口もありません。**動いている製品の中では一度も呼ばれません**
- さらに、その行を手でデータベースに入れてみたところ、残高が
  `通常100,000 / ボーナス −1,500 / 合計98,500` になりました。**存在しないはずの1,500MPが
  余分に引かれます**（ボーナス残高がマイナスになる）

つまり、いま呼ばれないだけでなく、呼ぶようにすると別の狂いが出る状態です。

### E5 得点とボーナスの換算表を、管理者が画面から変えられない

換算表そのものは正しく働きます（60点→500MP、80点→1,000MP、100点→1,500MP を実測）。
テストごとに別の表を持てる作りにもなっています。

しかし基準が求めている「管理者が**画面から**変更できる」手段がありません。

- 管理画面にテスト設定のページがありません
- 変更用の API もありません（`/admin/` にある入口は 企業一覧・購入ログ・取引の偏り・
  パスワード初期化・購入 の5つだけ）
- 変えるにはデータベースを直接書き換えるしかありません

### F1 トップページに「Featured」枠が無い

枠を買うところまでは正しく動きます。

- `POST /store/ads`（7日）で 3,500MP が引かれ、ボーナスから先に消えました
- `GET /store/ads` を直接呼ぶと、買った枠がちゃんと返ってきます

問題は、**生徒が見るトップページがその枠を一度も取りに行っていない**ことです。

- 生徒の画面のコード全体を調べても `GET /store/ads` を呼んでいる場所がありません
  （呼んでいるのは自社の広告一覧 `/store/ads/mine` と、枠を買う `POST /store/ads` だけ）
- 実際にブラウザで広告を出したあとトップページを開き直しても、Featured の欄は出ず、
  表示回数は 0 のままでした

お金を払って買った枠が、買い手の目には一切触れません。広告を出しても売上が変わらないので、
「広告費を出したら売上がどう変わるか」という授業の狙いがこのままでは成り立ちません。

## 満たしてはいるが、知っておいたほうがよいこと

### 前書きの「既定値は管理者が画面から変更できるようにする」が4か所とも未実装

`docs/requirements.md` 第2部の前書きに「**既定値**と書いたものは管理者が画面から
変更できるようにする」とあります。**既定値**と書かれた4つの数字は、いずれも
画面から変えられません。

| 数字               | どこ | いまの状態                                             |
| ------------------ | ---- | ------------------------------------------------------ |
| 初期資金 100,000MP | B2   | プログラムの中の固定値（「あとで対応する」と注記あり） |
| 失敗5回・15分      | A6   | プログラムの中の固定値                                 |
| 得点→ボーナスの表  | E5   | 変更手段なし（→ 満たさないと判定）                     |
| 相互取引率 30%     | H2   | 画面に入力欄なし（URLに書けばAPIは受け付ける）         |

E5 だけは基準の文にも「画面から変更できる」と書いてあるので満たさない判定にしましたが、
残りの3つも同じ状態です。

### A4 再発行コードを入力する画面が生徒には無い

仕組みとしては完全に動きます（使う→新しいコードが1回だけ出る、古いコードは二度と使えない）。
ただし生徒の画面には**入力する場所がありません**。ログイン画面には
「パスワードを忘れたときに使います」という説明文だけが出て、入力欄もリンクもありません。
生徒がパスワードを忘れたら、いまは先生に頼むしかなく、その先生の画面も A5 のとおり
用意されていません。

### D5 売った側は「誰が買ったか」が見えない

買った側の履歴には相手の企業名が出ます。売った側の履歴は、商品名は出ますが
相手の欄が空です。Market ID が漏れていないという点では基準を満たしていますが、
「誰に売れたか」は売り手には分かりません。

### テストの問題文は日本語のままで、翻訳の仕組みが無い

画面の文字（ボタン・見出し・説明）は6言語すべてそろっています。しかし
テストの問題文と選択肢は日本語で保存されており、英語やタイ語を選んでも
日本語のまま出ます。基準 I2 は「UI 文字列について」と書いているので判定には
影響させていませんが、要件34は翻訳対象に「テスト」を挙げています。

### 管理画面の土台（Mercur が元から持つ部分）は英語のまま

足した3ページには言語切替があり6言語になります。一方、ログイン画面や
Orders / Products / Settings といった元からある画面は英語のみです。
また左メニューの「企業一覧」などの文字は起動時に決まるため、言語を変えても
開き直すまで元の言語のまま残ります。

### I4・J1 は本来「人が確かめる」基準です

- **I4**: 私が英語だけで最後まで操作し、途中で行き詰まる箇所はありませんでした。
  ただし基準の文は「人が実際に操作して確認」です。**簡体字・ベトナム語・ネパール語・
  タイ語は、その言語を読む人が一度も見ていません**（タイ語の画面が全て訳されて
  いることは私が目で確認しました）
- **J1**: 私がスクリーンショットを見て、禁止されたモチーフが無いことを確認しました。
  こちらも基準の文は「チェックリストで人が確認」です

### K3 は「入口が無い」ことで守られていて、データベース側の強制はありません

履歴を書き換える・消すHTTPの入口は存在しません（実際に試して全て404）。
ただしデータベースには更新・削除を禁じる仕掛け（トリガーや権限の制限）は無く、
「そういうコードを書かない」という約束で守られています。また、取り消し（逆仕訳）を
作る入口もまだ無いので、間違えた取引を打ち消す手段は現時点でありません。

## リリースしてよいか（私の意見）

**いまのままリリースするのは勧めません。** ただし作り直しが要る状態ではありません。
7件のうち5件は「作りかけの部品が画面や定期処理につながっていない」だけです。

授業で使う前に直したほうがよいと思う順に並べます。

1. **F1（広告がトップページに出ない）** — 授業の中心にある「広告を出すと売れるか」を
   試せません。生徒はお金を払って何も起きない体験をします
2. **A3（個人情報を入れられるAPIが開いている）** — この仕組みの一番の売りが
   「個人情報を持たないこと」です。生徒がその画面を持っていないとはいえ、
   入口が開いたままなのは、匿名を前提に学校へ説明したときに困ります
3. **A5＋A4（パスワードを忘れた生徒を助けられない）** — 60人規模で7日以上使えば
   必ず起きます。いま起きると、先生も画面からは何もできません
4. **E2＋B3（ボーナスの期限切れ）** — ボーナスの期限は7日です。**8日目に必ず起きます。**
   帳簿が合わなくなり、失効の行を足す処理を有効にすると今度は残高が余分に減ります
5. **E5（換算表を変えられない）・B1（企業名を変えられない）** — 授業の運用で
   「その場で変えたい」が起きやすいところです

一方で、**土台の部分は堅いという印象を持ちました。** 60社が同時に売買しても
残高も在庫も1件も狂わず、自社購入・残高不足・売り切れ・他人になりすました操作は
すべて正しく断られます。多言語の作りも、英語だけで最後まで操作できました。
画面も教材っぽさが無く、そのまま実在のサービスとして通る見た目です。

**5つの穴はどれも「あと一手つなぐ」種類のもの**に見えます。そこを埋めてから
もう一度この確認をやり直すのがよいと思います。
