# 公開の手順

生徒が自分の端末から使えるようにするための手順です。**まだ一度も実行していません**
（この開発環境には各サービスの資格情報が無く、外へ出す操作ができません）。

**なぜこの置き場所を選んだかは `docs/decisions.md`「42.」に全部書いてあります。**
費用・取り上げの条件・他社を採らなかった理由・一次情報の直リンクはそちらを見てください。
ここには**手順だけ**を書きます。

## 全体の形

**サーバーとデータを、わざと別々の会社に置きます。**

| 何を                                     | どこに                    | 費用         |
| ---------------------------------------- | ------------------------- | ------------ |
| **生徒のデータ**（企業・MP・取引の記録） | **Aiven** の PostgreSQL   | 無料・無期限 |
| サーバー本体（`apps/api` と Redis）      | **Oracle Cloud** の無料枠 | 無料・無期限 |
| 生徒の画面（`apps/storefront`）          | **Cloudflare Pages**      | 無料         |

**分ける理由（1行で）**: Oracle は使われていないと判断したサーバーを**予告なく取り上げる**
ことがあり、そのときデータが残るかを公表していないためです。データを別の会社に置けば、
取り上げられても失うのは「サーバーを作り直す時間」だけになります。

**この形なら、最悪でも次の手順で戻せます。** 下の「作り直す」を見てください。

---

## 1. データの置き場所（Aiven）

1. Aiven に登録する（**クレジットカードは不要**）
2. **PostgreSQL** の **Free プラン**でサービスを1つ作る
3. 接続先の文字列（`postgres://...`）を控える → これが `DATABASE_URL`

**無料枠は 1 CPU / 1 GB メモリ / 1 GB ストレージ**です。いまの規模（数百 MB）なら足ります。
**長期間まったく使わないと停止されます**（事前に知らせが来ます）。

## 2. サーバーの置き場所（Oracle Cloud）

1. Oracle Cloud に登録する（**本人確認のためクレジットカードが要ります。課金はされません**）
2. **本拠地リージョンは慎重に選ぶ**。あとから変えられません
3. **Ampere A1** の Compute インスタンスを作る（無料枠は 2 OCPU / 12 GB まで）
   - `out of host capacity` と出たら、別の可用性ドメインを試すか、時間をおいて再試行する
4. その機械の上で動かすもの:
   - Node 22 と pnpm
   - **Redis**（キャッシュなので、この機械の上でよい。消えても困らない）
   - このリポジトリ（`apps/api` を `pnpm run api:start` で起動）
5. 環境変数を渡す。キー名の一覧は `apps/api/.env.template`

| 変数名          | 中身                                                |
| --------------- | --------------------------------------------------- |
| `DATABASE_URL`  | 手順1で控えた Aiven の接続先                        |
| `REDIS_URL`     | `redis://localhost:6379`                            |
| `STORE_CORS`    | 生徒の画面の住所                                    |
| `AUTH_CORS`     | 生徒の画面の住所（**`STORE_CORS` と両方に入れる**） |
| `JWT_SECRET`    | 長いランダムな文字列（開発用の既定値を使わない）    |
| `COOKIE_SECRET` | 同上                                                |

**`STORE_CORS` と `AUTH_CORS` は必ず両方に入れてください。** 片方だけだと
**「市場は開けるのにログインだけ失敗する」**状態になります（実際に起きました）。

6. `pnpm run api:migrate` で表を作り、`pnpm run seed` で公開鍵と販売channel を作る
7. 出てきた**公開鍵**（`pk_` で始まる67文字）を控える

## 3. 生徒の画面（Cloudflare Pages）

このリポジトリをつないで、次の設定にします。

| 設定項目         | 値                                       |
| ---------------- | ---------------------------------------- |
| ビルドコマンド   | `pnpm --filter @sckool/storefront build` |
| 出力ディレクトリ | `apps/storefront/dist`                   |

**環境変数を2つ**入れてください。片方でも欠けると、市場に商品が1つも出ません
（公開鍵が無いと Store API が全て 400 を返すため）。

| 変数名                 | 中身                  |
| ---------------------- | --------------------- |
| `VITE_BACKEND_URL`     | 手順2のサーバーの住所 |
| `VITE_PUBLISHABLE_KEY` | 手順2で控えた公開鍵   |

**この2つは組み立てるときに埋め込まれます。** あとから変えたときは**組み立て直して**
ください（環境変数を変えるだけでは反映されません）。

---

## サーバーを取り上げられたときに作り直す

**データは Aiven にあるので、失われていません。** やることはサーバーを作り直すだけです。

1. Oracle で Ampere A1 のインスタンスを作り直す（上の手順2の1〜3）
2. Node 22・pnpm・Redis を入れる
3. このリポジトリを取ってきて、**同じ環境変数**を入れる（`DATABASE_URL` は変えない）
4. `pnpm run api:start` で起動する。**`api:migrate` と `seed` は実行しない**
   （表もデータも Aiven に残っているため）
5. サーバーの住所が変わったら、Cloudflare Pages の `VITE_BACKEND_URL` を直して組み立て直す

**`seed` を実行しないこと。** 公開鍵と販売channel を作り直すと、生徒の画面に入っている
公開鍵と食い違います。

## 授業の前に確かめること

**無料の置き場所には、どの会社も「必ず動き続ける」保証をしていません。**
授業の直前に、次の3つを開いて確かめてください。

1. 生徒の画面が開き、商品が並ぶ
2. 自分のアカウントでログインできる
3. 管理画面が開く

## まだ決めていないこと

- **独自の住所（ドメイン）を使うか**
- **本番用の運営者パスワード**。いまは開発用の既定値がコードに入っています。
  公開する前に必ず変えてください
- **データの控え（バックアップ）をどう取るか。** **Aiven の無料枠に自動バックアップは
  付いていない**（2026-09 に公式を確認。`docs/decisions.md`「42.」に記載していた
  「バックアップつき／1本」は誤りだった）。`pg_dump` で定期的に控えを取る運用にする
